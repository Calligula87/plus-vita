# Scrolling menus and focused artwork candidate

Tickets: #41 (control mapping), #42 (ordinary menus), #43 (catalogue).
The approved [spec](specs/scrollable-menus-and-focused-cover-preview.md) defines
behavior and the shared app/UI-flow/painter test boundary. Source starts at
`c19cbdb`. This is development work, not an accepted stream build.
Earlier hardware-validation tickets remain open and retain their separate gates.

## Software validation

The app view exposes stable item focus, total items, first visible item, bounded
visible rows and viewport geometry. Control mapping prepares five rows; catalogue
prepares seven. Ordinary menus use the same bounded list/navigation contract,
while short menus retain all their actions. Scrollbars are position indicators.
Controller movement clamps and preserves the 400/160 ms repeat cadence. Touch
movement of at least 12 screen pixels cancels taps, with no scrolling momentum.

The production UI flow owns cover selection and the monotonic 3,000 ms dwell.
Only the highlighted game's URL becomes eligible. Cache display is gated too.
The six decoded 128x128 images, single worker and transfer/decode limits remain
unchanged. Cancellation is cooperative: navigation never waits for a live worker.
A new visit permits one failed-cover retry. Details can load immediately.

`tools/test-app-preview.sh` drives the real dispatcher, UI flow, painter, cover
worker, URL/DNS policy, downloader and decoder. Only external HTTP, device/font
APIs and the monotonic clock are fixtures. It checks actual transfer starts,
3,000 ms boundaries, rapid browsing, delayed cached display, dragging, details
return, failure/retry, immediate details, cancellation spanning the next dwell,
late output rejection, two-tap selection and account retirement.
`tools/test-app-branding.sh` covers visible focus/scrollbar extremes, nested
mapping return, ordinary menu boundaries, repeat cadence, drag cancellation,
extra contacts, transitions and sleep. Existing control-to-session persistence,
account and recovery checks remain part of validation.

Actual-font previews are generated by `tools/test-app-freetype.sh` under
`build/debug/app-freetype-host/`: `controls-layout.ppm`, `controls-inputs.ppm`,
`controls-actions.ppm`, `controls-inputs-4.ppm` through `controls-inputs-6.ppm`,
and `catalogue-0.ppm` through `catalogue-2.ppm`. They cover first/last scrollbar
positions, long-title ellipsis and Loading cover / Cover unavailable / No cover.
Compact rows reserve enough height for the real Noto Sans ascent/descent.

## Required hardware comparison

Keep the accepted v000 package and earlier comparison artifacts. Use the new
candidate's recorded SHA256 and `build=scrolling-menus-41-42-43-1` diagnostic
marker; record Vita/PS TV model, controller and exact observations.

- Navigate every binding and destination at both edges. Check held repeat,
  proportional scrollbar positions and restoration after choosing/backing out.
- Drag slowly and quickly, release, slide away, add/remove contacts, switch to
  physical controls, enter another screen and sleep/wake. No stale gesture may
  activate a destination. Verify no momentum and valid visible focus.
- Save, cancel and restore defaults; restart and Play. Check every physical and
  rear-touch input, PS TV availability labels and the fixed physical exit shortcut.
- Exercise Welcome, Settings, account/setup, Remember/Forget and confirmations,
  help, errors and recovery. Confirm readable prose and original operation/cancel
  behavior. The system keyboard/pairing UI remains system-owned.
- Browse the seven-row catalogue using controller-only PS TV and Vita touch.
  First tap highlights, second tap opens details; Cross opens immediately.
  Search and Back stay accessible, including Triangle/Circle shortcuts.
- Browse rapidly, pause for three seconds and drag longer than three seconds.
  Verify the old image clears, only the highlighted image appears after settling,
  and release starts a fresh interval. Check cached titles and missing artwork.
- Interrupt artwork connectivity, move away/revisit to retry, open details/Play
  during failures and return to the same filter/focus/viewport. Cancel search,
  apply/clear filters and check empty/zero-result states. Forget/change accounts
  while artwork is in flight; no previous-account artwork may reappear.
- Compare browsing feel/readability with the accepted build. Confirm streaming
  picture, sound, controls/releases and stop/restart remain acceptable. Keep the
  earlier #37/#38/#39 hardware checks separate and complete them as applicable.

Record actual Vita and controller-only PS TV results before accepting this build
or closing these tickets. Controlled HTTP counts establish reduced artwork
activity, not physical input response latency or total process memory use.
